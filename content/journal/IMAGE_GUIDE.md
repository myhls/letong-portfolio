# Journal Image Guide

## 目录与命名

每篇文章使用独立目录：

```text
site/assets/journal/<article-slug>/
├── 01-cover.webp
├── 02-gameplay.webp
├── 03-mechanism-diagram.webp
└── 04-discussion-note.webp
```

- `<article-slug>` 必须与 `manifest.json` 中的 `slug` 一致。
- 文件名使用小写英文、数字和连字符。
- 图片顺序使用两位编号。
- 不在文件名中写“最终版”“新版”“覆盖版”。

## 推荐规格

| 类型 | 建议尺寸 | 格式 | 建议大小 |
|---|---:|---|---:|
| 文章封面 | 1600 × 900 | WebP | 300KB 以下 |
| 游戏截图 | 宽度 1200—1600 | WebP | 400KB 以下 |
| 机制关系图 | 宽度 1200—2000 | WebP / SVG | 250KB 以下 |
| 讨论配图 | 宽度 1000—1600 | WebP | 300KB 以下 |

所有截图应保留清晰 UI。示意图避免使用低分辨率截图放大。

## JSON 元数据

每张图片必须在 `manifest.json` 中登记：

```json
{
  "src": "../../assets/journal/<article-slug>/02-gameplay.webp",
  "alt": "图片内容的具体描述",
  "caption": "图片在正文中展示的图注",
  "source": "本人截图 / 游戏官方素材包 / 访谈链接",
  "credit": "游戏名称、作者或版权方",
  "license": "授权方式、使用范围或“仅限评论引用”",
  "placement": "after-section-2"
}
```

字段要求：

- `alt`：必填，描述图片传达的信息，不重复图注。
- `caption`：必填，说明图片与正文的关系。
- `source`：必填，说明素材从哪里获得。
- `credit`：商业游戏截图和第三方素材必填。
- `license`：必填；不确定时不得发布。
- `placement`：可选，供构建器插入正文指定位置。

## 来源与版权规则

- 本人游戏截图：注明游戏名称和截图时间。
- 游戏官方素材：注明官方素材包、官网或发行商。
- 外部文章、论文或访谈：记录标题、作者、链接和访问日期。
- 玩家社区截图：确认许可，记录原帖和作者；无法确认时不使用。
- 不使用来源不明的表情包、饭制图、Wiki 截图或搬运图片。
- 截图只用于机制分析和评论，不暗示官方合作或授权。
- 图片中的账号名、聊天记录、个人信息和测试数据需要遮挡。

## 正文穿插方式

图片应出现在相关论证附近，不集中堆到文末。每张图片至少回答一个问题：

- 这张图帮助读者看见什么？
- 它支持哪个判断？
- 图注是否补充了截图中无法直接看出的背景？

## 构建检查

后续构建脚本至少检查：

- `src` 指向的文件是否存在。
- `alt`、`source`、`credit`、`license` 是否为空。
- 扩展名是否在白名单中。
- 文件名与 `slug` 目录是否一致。
- 同一图片是否被重复引用。
- 构建后 HTML 中的相对路径在项目站点子路径下能否访问。

## GitHub Pages 路径

公开项目基础路径：

```text
/letong-portfolio/
```

文章页必须使用经过构建器验证的相对路径。例如：

```text
../../assets/journal/<article-slug>/02-gameplay.webp
```

不要在文章正文中硬编码：

```text
/assets/...
/journal/...
https://myhls.github.io/...
```

这样未来绑定自定义域名时不需要批量改文章。
